# گزارش وضعیت ریفکتور — ۲۰۲۶/۰۹/۲۴

تغییرات زیر پیاده‌سازی شده‌اند. **کل Definition of Done سند `output/refactor.md` هنوز تکمیل نشده است**؛ موارد دقیق باقی‌مانده در انتهای همین گزارش آمده‌اند. سابقهٔ جزئی در [continuation-2026-09-23.md](continuation-2026-09-23.md) نگهداری می‌شود.

## تغییرات اعمال‌شده

- خواندن و نوشتن عملیاتی در Authorization، Organization، Geography، User، Identity، Notification، Outbox، Pricing، ServiceCatalog، Manifest، Operations و Consignment عمدتاً از مدل‌ها، روابط و castهای Eloquent استفاده می‌کند. تمام `toBase()`ها حذف شده‌اند. ۳۱ استفادهٔ باقی‌مانده از `DB::table` فقط متعلق به فرمان‌های محلی ساخت کاربر و fixture مرسوله است.
- Repositoryهای عبوری حذف شده‌اند. قراردادهای دسترسی Manifest به ماژول‌های مالک داده، gateway اعلان، رمزنگاری، clock، ذخیرهٔ bundle قیمت و سایر مرزهای واقعی حفظ شده‌اند. سرویس‌های داخلیِ اصلاح‌شده مستقیماً تزریق می‌شوند؛ ۳۰ interface تک‌پیاده‌سازی Operations نیز حذف شدند.
- wrapperهای `execute`، paginator و transaction سفارشی و بسیاری از Result/façadeهای تک‌مقداری حذف شده‌اند. `handle`، تراکنش Laravel و paginator بومی مسیر اصلی اجرا هستند. دادهٔ عمومی با Resource/serializerهای صریح از مدل‌ها جدا می‌شود.
- موتورهای قیمت‌گذاری و ماتریس با rule/facts/line/result نوع‌دار، enum و محاسبات decimal کار می‌کنند. نرخ دقیق بدون عبور از float ذخیره می‌شود. validation پیکربندی، خطای workbook، canonical fingerprint و قواعد precision مستقل‌اند.
- محاسبهٔ تعهد زمانی به Domain مستقل با policy/window/context/result نوع‌دار منتقل شده است. زمان اجرای عملیات تزریق می‌شود؛ تعهد پذیرفته‌شده از نسخهٔ ثابت سیاست استفاده می‌کند. تست‌های DST، microsecond، حدود بازه و تغییر نسخه وجود دارند.
- اطلاعات ساخت کاربر، مشخصات راننده/گره، تخصیص نقش، شناسه‌های نرمال‌شده و خلاصهٔ پروفایل end-to-end نوع‌دار هستند. ترکیب ماژول‌های User، Organization و Operations در adapter برنامه انجام می‌شود.
- واگذاری نقش، scope و بررسی delegation از snapshot محلی عملیات و خواندن/درج گروهی استفاده می‌کنند. policy شکل محدوده در Domain است. تکرار داخل درخواست و تکرار موجود در دیتابیس پیش از نوشتن ناقص رد می‌شود.
- خواندن گزینه‌های سرویس، برنامه‌ها، سیاست‌ها، نقش‌ها و قابلیت‌ها eager/batch شده است. ledger مرسوله و شواهد انتقال دسته‌ای ذخیره می‌شوند؛ قفل والد، ترتیب قفل‌ها، tenant، audit، outbox و rollback حفظ شده‌اند.
- قواعد مانیفست نتیجهٔ `ManifestEligibilityReason` enum برمی‌گردانند؛ پیام‌های فارسی/انگلیسی در serializer هستند. پارامترهای `object` در Application مانیفست به مدل واقعی تبدیل شده‌اند. ارجاع مسیر نوع‌دار است و ساخت Route Plan مدل ذخیره‌شده را بدون خواندن دوباره برمی‌گرداند.
- اعلان‌ها مستقیماً از مدل رسید و OTP استفاده می‌کنند؛ رابطهٔ کاربر eager است. دریافت دوبارهٔ رویداد و تعارض unique رسید همچنان idempotent هستند؛ SQL errorهای نامرتبط پنهان نمی‌شوند.
- ۸۹ جدول نصب آزمایشی PK عددی خودافزا دارند. FK نسخهٔ وضعیت عملیاتی و دو FK سلسله‌مراتب ناحیه نیز عددی‌اند؛ UUID عمومی و قرارداد HTTP حفظ شده‌اند. migrationهای schema، FK و invariant جدا شده‌اند و seed داده از schema جداست. جزئیات: [schema.md](schema.md)، [database-invariants.md](database-invariants.md).

## اعتبارسنجی

نتایج قطعی آخرین اجرا در [tests.json](tests.json) ثبت شده است. بررسی نحوی ۱۶۵۵ فایل PHP بدون خطا، بررسی named constructor arguments بدون mismatch، Composer معتبر با دو هشدار قبلی exact-version و فهرست routeها در محیط testing موفق‌اند. اجرای نهایی: **۳۱۲ تست اصلی با ۸۶۰۳ assertion و ۱۲۰ تست یکپارچه با ۲۲۲۶ assertion؛ صفر error، failure و skip**. Pint کل پروژه و `git diff --check` نیز موفق‌اند.

تست‌ها فقط از MySQL و Redis موقت و دیتابیس‌های `chabok_testing` و `chabok_refactor` استفاده می‌کنند. فایل `.env` و دیتابیس کاری کاربر تغییر نکرده‌اند. فرانت‌اند در این workspace وجود ندارد و ادعای تست آن مطرح نیست.

## تفاوت‌های رفتاری مشخص

- پیکربندی ناقص موتور مالی به‌جای مقدار صفر/پیش‌فرض خاموش خطای صریح می‌دهد؛ خطاهای precision در مقادیر بزرگ اصلاح شده‌اند.
- canonical آدرسِ پروفایل/گره فیلدهای اختیاری null و مختصات float دارد؛ نگهداری کلیدهای ناشناختهٔ آزاد در این DTOها تضمین نمی‌شود.
- lookup شناسه با ورودی خالی هیچ کاربری برنمی‌گرداند؛ مقدار رشته‌ای `0` همچنان حفظ می‌شود.
- پیمایش graph معیوب cyclic خاتمه می‌یابد. ورودی هندسی و workbook مخرب با خطای مشخص رد می‌شود.

## کارهای باقی‌مانده از درخواست سراسری

1. **FK عددی:** بیشتر روابط هنوز به UUID عمومی unique ارجاع می‌دهند. تبدیل آن‌ها نیازمند تغییر هم‌زمان schema، روابط، queryها، adapterها و تضمین‌های tenant است؛ انجام‌شده محسوب نمی‌شود.
2. **دادهٔ ساختاریافته:** ورودی محاسبه/شبیه‌سازی قیمت، بخشی از draftهای کاتالوگ و quote/consignment، و بعضی projectionها هنوز associative array هستند. DTO/Resource سراسری کامل نیست.
3. **نوشتن در حلقه:** بخشی از پردازش ردیف‌های مانیفست و عملیات task/route همچنان per-item است. تطبیق spatial برای هندسه‌ها نیز بررسی گروهی بیشتری لازم دارد.
4. **سادگی و vocabulary:** بعضی interfaceهای داخلیِ ماژول‌های دیگر، handlerهای طولانی و رشته‌های lifecycle/status هنوز بازبینی سراسری نشده‌اند. حذف interface صرفاً به‌خاطر شمارش، جای بررسی مرز واقعی را نمی‌گیرد.
5. **invariantهای دیتابیس:** ۹۰ trigger لازم برای تضمین‌های مستقیم SQL حفظ شده‌اند؛ حذف آن‌ها بدون جایگزین هم‌ارز، رفتار و امنیت داده را تغییر می‌دهد. جزئیات و توجیه‌ها در سند invariantها ثبت‌اند.
